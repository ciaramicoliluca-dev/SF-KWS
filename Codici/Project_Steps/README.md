I file corrispondono ai seguenti step:



1. Google\_Speech\_Extractor: Download ed estrazione del dataset GSCD V0.02 in una cartella dedicata;
2. Speech\_CSV\_Divider: Divisione del dataset mediante il file di testo presente nel GSCD in Train/Validation/Test in 3 file CSV dedicati, contenente la classe di riferimento e la label; Inoltre, nel file Single\_MFCC\_extraction\_2b viene testata l'estrazione delle features MFCC di un singolo file audio e visualizzazione dello spettrogramma risultante dei coefficienti;
3. Full\_MFCC\_Extraction: Estrazione dei coefficienti MFCC di una singola suddivisione di tr/val/tst e salvataggio dei parametri in formato npz. Inoltre, in MFCC\_Spectrogram\_Generator\_3b otteniamo un'immagine dai file NPZ per la visualizzazione dello spettrogramma per ogni classe;
4. DS\_CNN\_Model: Creazione dell'architettura di rete, basata su una semplificazione della MobileNet proposta nel paper "Hello Edge: Keyword Spotting on Microcontrollers" espresso in tabella 7, risultante in 38.6KB e 5.4M di operazioni. Il riepilogo dei layer, con 24.908 parametri totali, è salvato in Architecture.txt;
5. Training\_5: Addestramento della DS-CNN con i parametri di "Hello Edge": ottimizzatore Adam, batch size di 100 e 20000 iterazioni, convertite in 54 epoche in base alla dimensione reale del train set. Il learning rate parte da 5e-4 e scende a 1e-4 a metà addestramento per ridurre l'overfitting. Non viene fatta data augmentation, vista la dimensione del batch. Il modello con la migliore accuratezza di validation viene salvato in ds\_cnn\_s\_best.keras e la storia dell'addestramento in training\_history.json. Il miglior risultato è il 93.9% di accuratezza di validation all'epoca 30. Il test set non viene toccato, perché serve solo per la validation on target. Per controllare l'andamento, Training\_visualization mostra i grafici di accuracy e loss su train e validation, mentre Matrice\_di\_confusione calcola la matrice di confusione del modello sul validation set;
6. Conversione\_tflite\_6: Conversione del modello addestrato in TensorFlow Lite, in due versioni. La prima resta in float32 (ds\_cnn\_s.tflite, circa 99KB). La seconda è quantizzata a int8, con ingresso e uscita int8 (ds\_cnn\_s\_int8.tflite, circa 48KB): per la calibrazione si usano 100 campioni del validation set, da cui vengono registrati i valori minimi e massimi delle attivazioni. Infine, Conversione\_npy porta le features di validation dal formato npz a un file npy float32 di forma (N, 51, 10, 1), il formato che STM32Cube.AI Studio si aspetta per la validazione del modello.
